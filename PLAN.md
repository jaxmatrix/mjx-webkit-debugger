# mjx-webkit-debugger — Roadmap

The living, public roadmap. For architecture rationale see [`CLAUDE.md`](CLAUDE.md); for the frozen
interfaces see [`docs/SEAMS.md`](docs/SEAMS.md).

## Objective

A native, cross-platform debugger for WebKit programs that reaches Chrome-DevTools parity where the
protocol allows it, and that **cannot be taken down by the program it is debugging**.

## Guiding principles

1. **Every phase ships a working version.** Phase 1 is not scaffolding for Phase 2 — it is a source
   browser you can use. Later phases add capability to a product that already works.
2. **The whole seam is frozen up front**, so phases nobody has scoped yet already have a shape and
   their tasks can be written today.
3. **No webview in the shipped graph**, ever.
4. **WebKit's vocabulary above the dialect layer**, even when the wire is Chromium's.
5. **Fixture-driven** — every task testable with no browser running.
6. **Say what is true** — gaps are documented, not hidden.

## Release gates

- **v0.1.0 — Phase 1: a working source browser.**
  - *1a — seam freeze.* ✅ *done.* Workspace and 17 crates compiling; the complete `docs/SEAMS.md`
    landed as real Rust; `mjx-wk-protocol` generated from WebKit's descriptions (27 modules, 26
    domains, 239 commands, 110 events) with the output committed; `Transport`/`Dialect`/`DomainAgent`/
    `Panel` traits; a fully working `ReplayTransport` and `WebKitDialect`; the `xtask` recorder,
    codegen, and both verifiers; CI; all guidance docs; task files for every phase.
  - *1b — the source browser.* Attach to a running WebKitGTK app, discover targets, inventory every
    script and resource, fetch and cache source, virtualised syntax-highlighted code view, file
    tree, search, pretty-print. Ten parallel tasks, T-001…T-010.
- **v0.2.0 — Phase 2: a working debugger.** Breakpoints (line, conditional, logpoint, DOM, event,
  XHR, exception, symbolic) with WebKit breakpoint actions and probes; stepping; call stack with
  async frames; lazy paginated scope and variable tree; watch expressions; evaluate-on-call-frame;
  source maps; blackboxing; the console panel.
- **v0.3.0 — Phase 3: Apple platforms and network.** `AppleLocalTransport` (macOS `webinspectord`)
  and `AppleUsbTransport` (iOS ≤16) — debug Tauri apps on macOS and iOS — plus the Network panel:
  waterfall, timing, headers and bodies, WebSocket frames, HAR export, interception. Includes the
  iOS 17 RSD spike.
- **v0.4.0 — Phase 4: Chromium and Android.** `CdpDialect`, `CdpTransport`, and
  `AndroidAdbTransport` — debug Tauri apps on Windows and Android, and validate the whole
  application against Chromium WebViews. `AppleRsdTransport` if the spike says it is needed.
- **v0.5.0 — Phase 5: profiling.** `Timeline`, `ScriptProfiler`, `CPUProfiler`, `Memory`, `Heap`;
  flame graphs, heap snapshots, retaining paths.
- **v0.6.0 — Phase 6: elements and styles.** DOM tree, matched and inherited rules, computed
  panel, live editing, grid and flex overlays.
- **v0.7.0+ — Phase 7.** Storage and application, canvas and shader inspection, layer tree,
  animations, audits. Then WebAssembly debugging, whose shape the seam already allows.

Phases 3–7 are L4 peers and can run in parallel once Phase 1 lands.

## Settled design decisions

- **UI → egui + eframe + wgpu + egui_dock.** Dual MIT/Apache-2.0, mature on all three desktop
  platforms, GPU-rendered, and — the deciding factor — not a webview.
- **Protocol types → generated by `xtask`, output committed.** No `build.rs`; regenerating is a
  reviewable diff. `verify-protocol` diffs the result against the WebKit actually installed, so an
  upgrade is caught at build time.
- **Testability → recorded traces.** `ReplayTransport` implements the same `Transport` trait as a
  socket, and treats a send the trace does not cover as a failure, so a fixture is a contract
  rather than a stub.
- **Dialect over neutral model.** Everything above L1 is WebKit-shaped and CDP is translated into
  it, rather than both being mapped onto an invented third vocabulary that would be lossy in
  whichever direction it did not favour.
- **Threading → one session task, one UI thread, `ArcSwap` snapshots between them.** The UI thread
  never awaits.

## Versioning

Pre-release `v0.0.x` until Phase 1b completes. Each release gate above advances the minor version.
The public API is not stable before `v1.0`.
